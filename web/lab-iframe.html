Lab: cross-origin iframe → postMessage

Goal
Learn why you must validate event.source and event.origin in a content-script message bridge.

The iframe below is served from http://127.0.0.1:8000 while this top page is http://localhost:8000.

Even though both look “local”, they are different origins. In the real world, if your extension runs on a site that embeds third-party iframes (ads, chat widgets, analytics), those frames may be able to message the top window.

In DVCE vulnerable mode, a content script that doesn’t check event.source/event.origin can accept messages from a cross-origin iframe and forward them to privileged extension code.

What the iframe sends

Show iframe sender snippet (runs inside the iframe) 
parent.postMessage(
  { dvce: true, cmd: "setBadge", args: { text: "IFRM" } },
  "*"
);

What the extension should do

In DVCE fixed mode, dvce/extension/content.js requires event.source === window, so iframe messages are ignored.

Show the relevant fixed-mode check (content.js) 
if (currentMode === "fixed") {
  if (event.source !== window) return; // blocks iframe window
  if (!isAllowedLocalOrigin(event.origin)) return;
}

Try it

  1. Set DVCE mode to vulnerable and refresh this page.
  2. Click Send setBadge inside the iframe; the extension badge should change to IFRM.
  3. Now toggle DVCE mode to fixed and refresh; the badge should no longer change.
