Lab: Weak update / publisher security

Extensions auto-update for users. That’s great for patching—but it also means a compromised publishing pipeline can become a rapid mass-infection vector.

Key idea
If an attacker can publish an update (dev account takeover, CI compromise, malicious dependency), users may receive it automatically.

What can go wrong

  • Developer account takeover → attacker uploads a malicious version.
  • CI/CD compromise → build artifacts are modified before publishing.
  • Supply chain compromise → dependency update adds malicious behavior.
  • Weak review/release process → unsafe code reaches production.

How to secure (practical checklist)

  • MFA everywhere: Chrome Web Store publisher, source control, CI.
  • Least privilege: only a small set of accounts can publish releases.
  • Protected branches: require PR reviews and status checks.
  • Reproducible builds: make it harder to hide tampering.
  • Dependency control: lockfiles, review diffs, SCA scanning.
  • Monitor releases: alert on unexpected permission changes or behavior changes.
