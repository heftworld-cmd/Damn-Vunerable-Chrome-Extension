Lab: web_accessible_resources leak

Goal
Learn how websites can load extension-packaged files via chrome-extension://<extension-id>/... when those files are listed in web_accessible_resources.

This lab loads dvce/extension/public/leaked.js via a <script> tag using your extension ID. If an extension exposes resources broadly and includes secrets in the package, websites may be able to load and read them.

Where this is configured

In dvce/extension/manifest.json, DVCE exposes one file to local pages:

Show manifest snippet 
"web_accessible_resources": [
  {
    "resources": ["public/leaked.js"],
    "matches": ["http://localhost/*", "http://127.0.0.1/*"]
  }
]

Try it

  1. Open chrome://extensions and copy the DVCE extension ID.
  2. Paste it below and click Load leaked.js.


    

    
Real-world implications

    
    
      
  • 
        If an extension ships sensitive data inside the package (API keys, tokens, internal endpoints) and exposes it via
        web_accessible_resources, any allowed website can read it.
      
    • 
      
  • 
        Even if you don’t expose secrets, exposing HTML pages or broad resource patterns can create unexpected attack surface
        (phishing pages, parameter reflection, etc.).
      
    • 
    


    
How to secure

    
    
      
  • Don’t ship secrets in extensions (treat the package as public).
    • 
      
  • Keep web_accessible_resources minimal and tightly scoped with matches.
    • 
      
  • Prefer messaging APIs to serve data dynamically with authorization checks.
